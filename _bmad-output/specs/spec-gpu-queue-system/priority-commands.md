# 优先级命令交互

由bmad-spec依据.memlog.md及已确认D037–D038提炼，补充Story3.1和3.2的各9组验收，不覆盖原PRD或AD中的优先级规则。尚未实现或测试。

## 已确认：紧急申请审核

- 紧急申请待审或被拒绝时继续普通排队，提交时间和接收序号不变。批准后仅仍在等待的卡参与紧急组排序；等待超过72小时的组仍按既定规则优先。
- 审批前已部分/全部获配时，不追溯改分或修改原名额及期限；全部已获配时仅记录审核结论和对应通知/审计。
- 首次审核形成结论，本故事不提供事后改判入口。原command_id同载荷返回原结果，同键异载荷409；新键重复同结论返回已处理且无变化，新键试图反向改写结论409。
- 批准或拒绝必须有非空理由，审核状态、命令结果、完整审计与站内消息同事务提交；多卡按既定顺序加锁，审批与分配重读最新状态。
- 公开队列仍只显示在排姓名与顺序，不泄露他人审核详情。

## 已确认：当前等待项调序

- 管理员选择单卡当前等待项、目标位置、所见有序队列快照，带非空理由提交；锁后当前有序列表与所见不同则409刷新确认，不静默把旧位置应用到新队列。
- 有效顺序严格使用AD-7的基础排序和移动重放算法；调序不改原提交年龄、接收顺序或紧急结论，不生成永久成员权重。
- 目标项及同卡位置发生变化的在排成员收到原因与本人位置变化通知，每成员每次转换只一条；不附带他人申请详情或完整审计。
- 原command_id同载荷返原结果，异载荷409；新键的新移动以最新快照为准。移至当前位置且顺序不变时返回无变化，不重复规则、成功干预审计或业务通知。
- 目标离队后有效移动规则失效，后续申请不继承；清理有效规则不得删除原审计。移动、幂等结果、完整前后顺序审计及全部必需消息同事务保存，失败整体回滚。
