# 架构一致性验证计划

状态为验收设计，待实现后执行。使用独立 H2 临时文件库，按顺序操作并核对持久化结果。时间边界使用可控 UTC 时钟。

| 场景 | 执行方式 | 通过条件 |
| --- | --- | --- |
| 同卡唯一及交接 | 一张空闲卡有多条合法等待项，触发分配、重复触发，再归还或撤销 | 当前名额唯一，初次和后继均按有效排序获配，历史与映射一致 |
| 旧名额隔离 | A101 结束后 A102 获配，再依次提交 A101 的旧归还、撤销和到期处理。覆盖同一成员两轮 | A102 身份及期限不变，不另行分配、通知或追加成功审计 |
| 续期先处理 | 先批准续期，再在原到期时间执行检查 | 读取新期限，当前名额继续有效 |
| 释放先处理 | 先释放不足 24 小时的未开始名额，再审核旧续期 | 旧续期失效，原名额和后继记录均不变 |
| 保留名额后续期 | 先标逾期或异常，再批准延期 | 有效名额可延期。逾期随期限更新，未开始异常保留 |
| 短时续期（D039） | 分别将 6 小时延至 12、24、30 小时，并检查待审场景 | 12 小时到期未开始释放。24/30 小时在原分配满 24 小时标异常，并保留。待审不改变期限 |
| 开始或归还与到期 | 顺序演示各自先处理和到期先处理，覆盖 23/24/25 小时 | 按 PRD 释放、异常或逾期保留，旧操作不改后继 |
| 再次逾期与重复扫描 | 先逾期，再延期并到达新期限，重复扫描 | 新一轮可新增一次逾期通知，重复扫描无副作用 |
| 代表性失败回滚 | 令一项必需审计或消息写入失败，核对业务和记录 | 业务、映射、必需记录整体回滚，提交前不显示成功 |
| 排序与调序 | 检查等于/超过 72 小时、紧急审核、部分分配、时间并列、同人重复申请、人工移动锚点离队 | 查询与分配顺序一致，等待年龄不重置，移动只作用于当前等待项 |
| 权限和审计 | 逐类执行合法干预和绕过页面的越权请求，核对账号及归属权限 | 合法操作可用，越权无数据变化或泄露，成功干预均有必需理由、前后状态及通知 |
| 重启、备份与恢复 | 本机停止并重启观察持久化和补查，停机后手动复制数据库文件，在独立副本核对映射、历史后启动 | 记录能重读，启动按当前状态补查，原演示库未被覆盖 |

记录 H2 实际依赖版本、测试数据位置和迁移版本，保存操作顺序、目标标识、当前映射、历史、审计及消息证据。实验 A 按课程设计单独记录。
