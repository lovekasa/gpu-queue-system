# 管理员创建成员账号

依据 FR-001、AC-001-3、NFR-002、AR-14、AR-16、AD-1 和 AD-8，交付管理员建号表单及 `POST /api/admin/members`。新账号复用 Story 1.1 的 Session 登录入口。管理员在线下向成员交付初始凭据。

## 输入与结果

- 登录名沿用 `Account.normalizeLoginName`，去掉首尾空白，用 `Locale.ROOT` 转小写，规范化后长度为 1 至 128 个 Java UTF-16 代码单元。数据库唯一约束覆盖成员与管理员。
- 显示姓名去掉首尾空白，长度为 1 至 128 个 Java UTF-16 代码单元。初始口令不能为空，按输入原样使用 PBKDF2 散列。
- 请求表单包含 `loginName`、`displayName` 和 `password`，角色由服务端固定为 `MEMBER`。成功返回 201 和新账号标识、规范化登录名、显示姓名及角色。
- 未认证返回 401，无权限或无有效 CSRF 返回 403。输入无效返回 400 并指出字段，登录名冲突返回 409，持久化异常返回 503。
- 复用 V1 账号表。创建使用单条插入，冲突不覆盖原账号。响应和验收证据不包含口令、散列或会话值。
