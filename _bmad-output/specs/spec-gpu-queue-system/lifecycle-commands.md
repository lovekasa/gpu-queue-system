# 名额生命周期命令交互

由bmad-spec依据.memlog.md及已确认的D031、D032、D034、D039、D040、D041、D042提炼。本文补充PRD及架构中的命令交互，不代替其权限、事务或身份约束；候选故事尚未接受的处理不在此声明为已定。

## 已确认：按卡开始

- 开始只记录成员的网页声明，不启动、探测或停止训练任务；每张卡独立操作，不重置分配时刻和到期时间。
- 同一操作者以相同command_id、相同载荷重试，验证有权访问结果后优先返回原成功结果，不能因名额随后已结束而误报本次重试失败。
- 用新command_id重复开始当前已开始名额，返回可辨认的已开始且无变化结果；不覆盖首次started_at，不重复成功转换审计或业务消息。
- 同键不同载荷为冲突；旧名额没有可返回的原结果时按失效处理，不复活旧名额或改变后继名额，即便两次持有者相同。
- 开始事实、转换记录、幂等结果及必需审计同事务保存，失败全部回滚；保留已存在的历史异常事实。

## 已确认：按卡归还

- 成员确认完成并归还当前本人名额后立即释放，无需管理员审批；只结束指定卡的原名额，不影响同申请其他卡或等待项。
- 同一卡归还和存在合法等待项时的后继分配在一个事务中完成，名额结束、映射更换、幂等结果、必需审计及后继获配消息同提交；任何必需步骤失败则整体回滚，不能向页面报告成功。
- 后继获配使用新的allocation_id，即使持有者仍为同一成员；无等待项时不虚构名额或消息。
- 原command_id同载荷经权限验证后优先返回原成功；新command_id对已结束名额得到可辨认的已结束且无变化结果，不改首次结束时间，不重复分配或业务副作用。
- 归还只记录使用权结束，不访问服务器停止或检查任务；历史保留RETURNED原因和原分配/开始事实。

## 已确认：管理员核实释放

- 管理员查看仍有效的异常/逾期名额，提交目标allocation_id、所见状态版本、核实确认、非空理由及command_id。
- 未开始异常需核实可释放；已开始逾期需核实任务完成。未核实或条件不满足则保留名额，不能以本入口执行无需等待任务完成的主动撤销。
- 同键成功结果仍按权限和幂等约定优先返回；原名额仍有效但状态或版本与所见不符时409并刷新重新核实，不能沿用旧“未开始”判断释放已开始名额。原名额已结束按失效/已处理规则无变化处理，不改后继。
- 核实释放、后继分配、原成员处理通知、后继获配消息和完整审计同事务；理由、操作者、时间及前后状态不可丢失。必需写入失败整体回滚。
- 系统只记录管理员的线下核实声明，不冒称测得服务器任务状态。

## 已确认：成员续期与审核

- 本人对仍有效的指定allocation_id提出明确期望新到期时间；申请本身不延时。管理员批准值须晚于锁后最新当前期限及数据库当前时间，无额外单次/累计续期上限；首次72小时上限不能变成续期上限。
- 待审或拒绝不暂停到期处理，拒绝不撤销名额；仍有效名额可再次申请。已开始逾期但保留名额可续期，延期不清未开始异常、不改原分配/开始事实。
- 到期和批准同锁：批准先成功重读新期限；释放先成功审批无效，不复活旧名额。只标异常/逾期而仍保留时可以合法续期。
- D039关闭RENEWAL-EDGE-1：按当前已批准expires_at减原allocated_at总跨度判断是否不足24小时，24小时阈值不重置；6→12小时到期未开始释放，6→24/30小时满24小时未开始先标异常保留。原申请时长不被重写，未批准请求不改变分支。
- 同一续期申请首次审核结论不被反向改写；原键同载荷返回原结果，异载荷409，新键同结论无变化、反向改写409。不同申请批准按锁后最新期限校验，不重复累加或缩短，所见名额版本变化须刷新重新审核。
- 期限/结论、幂等结果、完整审计和本人结果通知同事务，必需写入失败全回滚；延期后新期限再次到达仍可产生新的逾期通知，不按名额ID永久吞掉后续事件。

## 已确认：管理员直接延期

- 无需存在成员续期申请；管理员提交明确新到期时间、非空理由、所见名额版本及command_id。操作类型保留为直接延期，不伪造成成员申请或批准。
- 新期限必须严格晚于锁后最新期限及数据库当前时间，只延长不缩短；无额外单次/累计时长上限，不以首次72小时限制封顶。
- 不改allocation_id、持有者和原分配/开始事实；有效逾期名额可延期，未开始异常不自动清除，短时分支与原24小时阈值遵守D039。
- 与到期、归还、续期共用同卡锁和成功提交顺序。释放先成功不能复活旧名额；所见名额仍有效但版本变化409刷新，原键同载荷仍优先返原结果，重试不重复累加。
- 期限、命令结果、完整审计和持有者结果通知同事务，失败整体回滚；普通成员只能申请续期，不能调用直接延期。

## 已确认：管理员代成员归还

管理员核实已开始任务完成或未开始名额可释放，提交原 allocation_id、所见版本、非空理由与 command_id。锁后校验，版本变化返回409并刷新核实。保留实际管理员身份，以 RETURNED 记录结束原因，审计标明代归还。原名额结束、后继获配、命令结果、完整审计及双方所需通知同事务。旧命令不能影响新名额，同键重试遵循既有幂等规则。

## 已确认：管理员主动撤销

管理员提交目标名额、所见版本、非空理由和命令标识，即使任务仍在运行也可撤销。界面提示由管理员线下通知原成员并协调交接。锁后发现原名额仍有效但版本已变时返回409，要求刷新确认。撤销、后继获配、幂等结果、审计及必需通知同事务提交；无后继则该卡在系统中可分配。旧事件只作用于原名额，数据库结果不能证明原任务已停止。
