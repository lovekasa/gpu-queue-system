# GPU 名额系统配套规格

本文件由 bmad-spec 从 .memlog.md 及其引用的已定稿材料提炼。完整契约由本规格和 companions 共同构成，所有下游必须读取frontmatter所列全部配套材料；FR、AC、NFR、AD 原编号保持不变。更新通过 bmad-spec 追加日志后重新提炼。

## Why

将约30名实验室成员对10张4090的纸质申请迁移到网页，提供可追溯的按卡排队、名额分配和归还流程，改善低年级获得使用机会的条件。管理员例外需透明；名额记录不能代表硬件真实占用，也不承诺最长等待期限。

## Capabilities

- **CAP-1**
  - **intent:** 管理员创建账号，成员以各自身份使用系统并按授权查看信息。
  - **success:** FR-001 的合法操作可用；成员越权管理员操作或查询他人详情被拒绝，他人在排信息只显示姓名和顺序。
- **CAP-2**
  - **intent:** 成员为一张或多张指定 GPU 提交普通申请，并可重复排队或持有多卡。
  - **success:** FR-002–004 验收通过：首次1–72整数小时，普通申请免审批，重复同卡不合并、不拒绝，仍遵守单卡唯一名额。
- **CAP-3**
  - **intent:** 成员按明确的队列规则获配指定卡，管理员可审批紧急申请和调整当前等待项。
  - **success:** FR-005–008 的按卡独立、部分分配、原提交时间、超过72小时等待提升、同级顺序、手动例外和按卡计时全部可复核。
- **CAP-4**
  - **intent:** 成员按卡确认开始，完成后归还以便后续成员使用。
  - **success:** FR-009、011 中按卡操作和归还立即释放成立；旧归还、旧撤销和旧到期均不能影响新名额，重复操作无重复业务副作用。
- **CAP-5**
  - **intent:** 系统区分未开始异常、短时自动释放及已开始逾期，管理员核实后处理。
  - **success:** FR-010–011及AC-012-4覆盖当前已批准总跨度不足24小时未开始到期释放、满24小时异常保留、已开始逾期保留，竞争事件按成功记录顺序判定。
- **CAP-6**
  - **intent:** 成员申请续期，管理员审核并按需代归还、延期、撤销使用权。
  - **success:** FR-012–014 验收通过；累计可超过3天且无单次/累计续期上限，已结束名额不复活；代归还须核实使用结束或名额可释放，记录实际管理员并原子交接；撤销可立即重新分配，无需等待任务完成或成员回执；页面提示管理员线下通知原成员并协调交接。
- **CAP-7**
  - **intent:** 成员查看站内消息，管理员追溯每次干预的理由和结果。
  - **success:** FR-015–016 覆盖干预及获配/异常/逾期/自动释放消息、已读和完整前后状态审计，第一版不自动删除记录。管理员可按申请或名额追溯干预，以实际成功操作清单逐笔核对完整率100%。
- **CAP-8**
  - **intent:** 成员查看自己的按卡状态、期限和历史，以及公开在排姓名和顺序。
  - **success:** FR-017–018 的部分分配、独立期限、结束历史和队列显示与实际排序一致，他人详情不会随队列响应泄露。

## Constraints

- D045 要求控制项目复杂度。复用单体应用和本地数据库，课程实验及试用评价优先以项目文档与简单表格完成。

- PRD 的18条FR、46条AC及NFR-001–003均为验收基线，不能以本文件摘要替代完整条款。
- 架构AD-1–8约束全部后续故事，尤其唯一当前名额、旧事件身份隔离、到期与续期成功事务先后、审计/通知同事务。
- 采用已确认的Vue3、Spring Boot3.3.13、Java21、本地MySQL模块化单体；精确前端与数据库服务端版本、基础故事参数依架构Deferred的时点核实，不冒称已锁定。
- D044 运行验收基线为每60秒扫描、每日备份。锁竞争测试配置为等待3秒，首次失败后最多额外重试2次。首次试用前在独立库还原，先核对映射与历史再补扫。
- 后续至少3个史诗、12个用户故事；课程要求至少5条ADR、项目上下文至少8条实现规则，并保存真实测试证据、冲刺历史与人机决策。已有8条ADR不能替代项目上下文文件。
- 实验A按PRD规定执行真实对照；至少15条真实决策、至少5条否决或实质修改AI输出是过程要求，不能将采纳或文档编辑凑作否决。

## Non-goals

- 不提交或执行训练任务，不接SSH，不终止进程，不监测真实GPU占用；违规运行线下协调，不增加处罚模块。
- 第一版不增加邮件/短信、Redis、独立消息队列或微服务；不做实验B及其专项影响分析。
- 本轮仅建立规格与拆分规划，不生成工程、实现业务或执行实验。

## Success signal

- 实现后PRD全部AC与三项NFR通过且保存证据：真实MySQL下同卡30次并发不重复分配且合法首项能获配，旧事件不影响后继名额，到期/续期两种顺序结果符合契约；越权失败、合法操作成功，干预审计完整。当前尚无执行结果。
- 公平性先观察年级等待与获配情况，同时观察长等待、逾期和人工例外；无基线不宣称改善百分比，名额次数不当作硬件利用率或任务完成数。

## Open Questions

- PRD Q09：需求负责人在试用评价设计前确定公平性观察窗口、基线、年级数据和统计口径，不阻塞规划提炼。
- PRD Q10：课程交付负责人在实验设计前核对实验A五项指标及团队分工，不编造对照结果。
- 架构Deferred：工程基础/运行故事按规定时点核实版本、持久化和迁移工具、D044配置的实际生效情况及备份恢复结果，必须保持AD契约。
