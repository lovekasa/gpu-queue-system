# 需求发现补充记录

状态：配套已完成产品简报的补充材料，2026-11-18 完成收尾。来源为多轮用户需求确认，未开展独立访谈或验证。当前规则以简报及本文件最新表述为准；历史修订保留在 decision-log.md 和 .memlog.md。

## 用户已确认

- 现状：纸质申请，高年级优先；希望低年级也能获得使用机会。
- 规模与形态：预计 30 名成员、10 张 4090，网页系统。
- 一个名额对应一张指定 GPU；一次可申请多个名额，不区分型号队列。
- 普通申请按提交时间排序，不需管理员审批；紧急申请必须管理员批准；长期等待者采用等待越久优先级越高的规则，已确认超过 3 天可排在紧急申请之前。允许管理员设置优先级、重复排队和同时持有多个名额。
- 申请时选定卡号；多卡申请允许部分分配。
- 最新规则：同一张卡按队列排序；甲部分获得 GPU 1、等待 GPU 2 时，乙可以获得空闲 GPU 3。
- 等待超过 3 天可超过紧急申请，管理员手动调序可以突破该保障。因此不承诺绝对的最长等待时间。
- 每张卡从各自分配成功时独立计时。
- 成员填写首次申请的预计时长，上限 3 天；分配成功开始计时；24 小时未点击开始，先标记异常，管理员核实后释放；续期需要管理员审核。
- 申请 6 小时，到期仍未确认开始，直接释放。用户已明确此规则；它与 24 小时未开始需核实规则的适用边界和风险接受理由待澄清。
- 到期未归还保留名额并标记逾期，等待管理员核实；仍在运行时等待任务完成才满足释放条件。
- 管理员撤销使用权时，不需要等待任务完成即可重新分配，构成上述等待完成规则的例外。系统不终止任务；管理员负责线下通知原成员停止使用并协调交接。
- 成员必须先点击“开始使用”再自行运行任务；这是使用约定，系统不控制服务器，无法技术上强制。
- 管理员批准后累计使用时长可以超过 3 天；第一版通知仅采用网页内站内消息。
- 管理员可审批、调整顺序、代为归还、延长时长和撤销使用权；必须填写理由、通知成员、记录操作前后状态。
- 用户要求可运行并实现分配管理，已确认一致性和权限隔离方向；具体测试参数留待 PRD 细化。

## 已确认的非功能需求方向与候选测试口径

- 一致性：对同一空闲 GPU 同时触发 30 次分配尝试，最多产生一条有效分配；重复归还不得重复触发分配。
- 权限：成员尝试审批、调序、代归还、直接延长使用时长或撤销等管理员操作时全部被拒绝，资源及申请状态保持不变。

用户明确一致性和权限隔离都要做。以上具体测试口径由 AI 提出，后续在 PRD 中细化确认，尚未执行测试。记录唯一性不等于真实 GPU 无任务冲突。
