### 1.2 项目上下文可执行实现规则（10 条，可追溯至已确认约定）
1. **单事务写入入口（AD-1 / NFR-001）**：所有排队、分配、开始、归还、到期、续期及管理员干预写入必须经 `AllocationService` 唯一 `@Transactional(rollbackFor = Exception.class)` 入口，业务状态、审计与站内消息同事务提交或回滚。
2. **同卡行锁与唯一映射（NFR-001）**：涉及名额变更的事务须按 `gpu_id` 升序调用 `lockGpu(gpuId)`，并通过 `current_allocations(gpu_id)` 主键保证每张 GPU 至多一个有效名额。
3. **版本化增量迁移不可篡改（AD-5）**：禁止修改已交付的 Flyway 迁移脚本（`V1`–`V15`），新增结构须以递增版本号增量迁移。
4. **可控 UTC 时钟与前端时区展示（AD-6）**：后端所有时间戳必须通过注入的 `Clock`（UTC）生成并以 ISO-8601 `Z` 持久化，禁止散落 `Instant.now()`；前端统一转换为 `Asia/Shanghai` 展示。
5. **公开队列字段严格隔离（FR-018）**：`GET /api/queues` 仅返回 `position` 与 `memberName` 两字段，禁止泄露申请时长、提交时间、审批理由、请求 ID 或内部标识。
6. **排序与分配同源（FR-007 / AD-7）**：公开队列查询与实际空闲分配必须复用同一 `QueueOrderingPolicy`（严格 `> 72h` 提升 > 已批准紧急 > 普通，再按 `queue_reorders.id ASC` 重放）。
7. **D039 未开始短时边界**：未开始名额是否走 `< 24h` 自动释放分支，始终按 `expires_at - allocated_at < 24h` 计算；24h 未开始异常阈值始终从原 `allocated_at` 计算且不因延期清除。
8. **受控角色与 CSRF 防护（NFR-002）**：所有变更请求必须携带有效 CSRF Token；`/api/admin/**` 仅限 `ADMIN`，本人资源严格按 Session 绑定 `memberId`，拒绝客户端伪造角色或审批状态。
9. **非空理由与乐观冲突保护（FR-013 / NFR-003）**：所有管理员干预必须提供非空理由（`<= 500` 字）并记录完整前后状态 `audit_logs`；所见状态/期限/队列快照过期时返回 `409`。
10. **本地独立 H2 验收隔离（D047 / D048）**：自动化测试与演示分别使用独立 H2 文件库目录，严禁提交 `.local-data/`、数据库文件或凭据。

## 4. 试用评价与公平性观察口径（Q09）

- **观察窗口**：建议连续 **2 周**（14 个自然日）实验室真实试用周期。
- **基线来源**：试用前 2 周实验室微信群/口头登记记录（若缺少精确时间戳，相关基线指标明确标为 `待验证`）。
- **年级/角色数据可用性**：仅在成员自愿提供年级标签时做匿名分组汇总；当前系统账号表未采集年级字段，按年级分层的公平性对比标为 `待验证`。
- **核心统计口径**：
  - **等待时长**：`allocated_at - submitted_at`（按卡独立计算，统计中位数与 P90）。
  - **获配率与名额周转**：区分 **“系统名额获配”** 与 **“实际物理 GPU 使用”**，系统仅度量名额使用权流转，不将名额状态等同于硬件实际利用率。
  - **长等待、逾期与人工例外观察**：
    - 长等待：统计触发严格 `> 72h` 等待提升的队列项占比。
    - 逾期与异常：统计 `audit_logs` 中 `MARKED_ANOMALY`、`MARKED_OVERDUE`、`UNSTARTED_EXPIRED` 发生频次与平均核实释放耗时。
    - 人工例外：统计 `EMERGENCY_APPROVED/REJECTED`、`QUEUE_REORDERED`、`RENEWAL_APPROVED/REJECTED`、`ADMIN_EXTENDED`、`ADMIN_PROXY_RETURNED`、`ADMIN_REVOKED` 各类干预占比及理由分布。
- **改善幅度计算原则**：**仅在取得同口径可比基线与试用期数据后才计算改善幅度**；数据不足项一律保持 `待验证`，不作推断或估算。
